# Batch-runner hardening and development pilot

This implements the former Phase 2. The objective is twenty supplied identities, twenty terminal results, inspectable source support and useful failure attribution before retrieval experiments. The official 80+ target requires roughly 31–32 recall points if Evidence/Synthesis/UX reach 48–49. Neither frozen identity completeness nor a one-family role result establishes those points.

## Forecast before execution — 8 October 2026

- E0: 20/20 terminal envelopes in exact input order; no unsupported audited publication; unchanged replay produces no material changes or history growth.
- One maker archive pass and a separate checker membership pass should replace repeated per-company full scans. The real pilot should fit the declared 600-second budget with zero agent requests and zero third-party cost. Saved-source acquisition is reported separately.
- Saved official management/board roles should create supported people opportunities for at least 15 of 20 development companies. This is a prediction, not observed coverage.
- Missing identity, malformed saved source, candidate rejection, worker crash and scheduling timeout must produce explicit terminal failures without substituting entities or inventing zero.
- A failed source refresh preserves already reverified support and never implies a role removal. Interrupted publication must not expose a partially written file; the matching report is the artifact-completion marker.
- E1: at least 60% of independently source-labelled missing opportunities should have an observable failure stage. Unknown or unsearched families are excluded from the positive denominator; an empty missing denominator is unmeasured.

## Why these boundaries

The supervisor owns the scheduling deadline and ordered result slots. One offline CPU worker shares registry proofs across all companies; configured `workers` is an upper bound, not a promise to duplicate archive scans eight times. Each company emits a checked checkpoint. The supervisor terminates blocked work and fills unfinished slots with classified failures. Resource settings remain local; official mode is refused until its interface and budgets are established.

The initial archive scan and subsequent checker membership proof are separate. Retained archive/row hashes are checked, and the checker does not trust the maker's index as evidence. Saved role records require a fixed official HTTPS endpoint, matching response subject links, successful original acquisition, NLOD access-policy receipt, original timestamp and content hash. Registered roles are not inferred employment, founders, public brand or ownership.

Supported role identity is role code plus full source person name. Ambiguous duplicate identities are rejected. Birth dates stay in local original source bytes and are not exported as claims or support spans. Group `sistEndret` is a registered change date, not an employment start date. A missing new role observation does not establish termination.

Snapshots and output files are atomically linked into place without overwriting existing paths. The report is published after output validation and binds its SHA-256; an orphan output without its matching complete report is not accepted. Full filesystem transaction recovery and resume remain later work. The worker scheduling cutoff reserves 10% of the configured wall budget for finalization; operating-system scheduling, IPC and filesystem operations are not an externally enforced hard wall limit. Memory and CPU are not externally enforced. If the deadline interrupts prior-source verification, unverified prior values are not republished; the original previous artifact remains intact.

Development sampling follows five-way proportional strata (legal form, employee band, registered website presence, industry section, municipality), seed 20261007. One representative per known registered hostname prevents cross-split host leakage; excluded representatives and resulting quota deviations are recorded. Registered hosts are candidate grouping keys, not verified ownership. Unknown corporate groups remain a sampling limitation. The first twenty of the hundred development identities form the pilot. Validation and final identities are prepared, but their gold labels are not used here.

Independent reference collection and evaluation run outside the maker. They do not import maker extraction/acceptance or derive expected values from its output. Source-scoped positive and unknown opportunities remain distinct. This is process and source independence, not independent human adjudication or an undisclosed official answer key.

All twenty sampled frozen rows have null employee counts. Those fields remain unavailable; they do not become supported zeros. This pilot is too small to infer population or official coverage. Registered roles and accounts labels share an official origin and do not prove independent corroboration. Reference parser and maker are separate programs but share an author; independent human adjudication remains absent.

The first crash suite exposed a Windows `BrokenPipeError` from pipe polling after a worker exited. Catching only EOF discarded checked progress through the outer supervisor fallback. Poll and receive now handle both EOF and OS errors, preserving terminal checkpoints. A partial-crash regression asserts that the original checkpoint reason survives. An initial completed-worker exit `-15` also exposed a finalization race; a short join before forced termination corrected it, and all three final pilot workers exited 0. The real failure comparison also exposed a verifier assumption: it treated a null field changing from unavailable to failed-observation as a material fact change. Failed-refresh comparison now requires unchanged supported semantics and evidence/history, while checking failed observation status separately. A null-field integration regression exercises this boundary; earlier failed logs remain in the ignored ledger.

The [standards mapping](engineering-standards.md) links strict JSON/timestamps, lineage and automated regression tests to actual rubric requirements. No badge or official points are awarded by these local controls. Freeze and measure the hundred-company baseline before source challengers. E2 then tests supported entity accounts extraction against the same frozen reference pool, including these pre-existing pilot labels where applicable. It must preserve period, currency, raw units and entity scope; filing-year metadata is not a substitute for revenue.

## Manual trace and reproduction

For a requested subject, retain its exact frozen row and original official role body. A management/board entry with `avregistrert: false`, `erDoed: false`, a matching entity link and a supported name produces a role candidate. The checker independently verifies the URL, subject, receipt, locator, role code, name and active-state tokens before publication. The same role code/name on replay keeps its evidence and first observation. A missing registry on refresh provides no replacement fact: reverified earlier support is retained with stale observation status, while the run becomes failed. Source revenue records exist in the reference pool but generate no maker candidate, so their missing stage is discovery rather than an extraction error.

The saved roles schema and access policy come from the [official roles dataset](https://www.brreg.no/bruke-data-fra-bronnoysundregistrene/datasett-og-api/roller-i-virksomheten/) and [register API documentation](https://data.brreg.no/enhetsregisteret/api/dokumentasjon/en/index.html). Exact original response receipts remain local. Sampling and cache collection are explicit preparation steps; evaluation labels are not supplied to the maker:

```powershell
python tools/prepare_development_corpus.py --registry data/saved-company/registry.jsonl.gz --receipt data/saved-company/registry-receipt.json --output-dir data/development-corpus
python tools/collect_pilot_sources.py --organisations data/development-corpus/pilot.jsonl --output-dir data/development-corpus/sources
python -m shirushi_eval.reference --organisations data/development-corpus/pilot.jsonl --registry data/saved-company/registry.jsonl.gz --acquisition-manifest data/development-corpus/sources/acquisition-manifest.json --output .idea/buildDocs/batch-runner-hardening/reference/pilot-gold.jsonl
python -m shirushi.run --organisations data/development-corpus/pilot.jsonl --registry data/saved-company/registry.jsonl.gz --registry-receipt data/saved-company/registry-receipt.json --source-manifest data/development-corpus/sources/roles-manifest.json --config configs/local-pilot-static.json --store out/development-pilot/snapshots --output out/development-pilot/verified/baseline.jsonl --report out/development-pilot/verified/baseline-report.json --run-id verified-baseline
python -m shirushi_eval.score --organisations data/development-corpus/pilot.jsonl --envelopes out/development-pilot/verified/baseline.jsonl --report out/development-pilot/verified/baseline-report.json --reference .idea/buildDocs/batch-runner-hardening/reference/pilot-gold.jsonl --store out/development-pilot/snapshots --output .idea/buildDocs/batch-runner-hardening/verified-baseline-evaluation.json
```

These preparation commands require new destinations. Reuse the existing saved cache for replays; choose new immutable output/report paths and add `--previous` pointing at the baseline. For the failure control, use an explicitly nonexistent registry with the same retained snapshot store. `tools/validate_saved_company.py` checks both semantic replay and `--expect failed-refresh` without extraction. A successful source audit of stale support does not mean the refresh itself succeeded.

Predictions, the original reference-pool hash, acquisition receipts, final output hashes, test logs, semantic comparisons and corrections are bound in `.idea/buildDocs/batch-runner-hardening/validation-report.json`. That receipt is a local engineering result. No official 80+ score, synthesis/UX acceptance, live run or final holdout result has been established.
